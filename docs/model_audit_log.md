# NetSage AI — Model Audit Log

This log tracks agreement between AI-proposed diagnoses and the human
reviewer's final decision, per the Responsible AI requirement: **at least
5 cases where the AI answer was corrected (Edited or Rejected) by a
human**, with an explanation of why.

New entries are appended automatically by `src/app.py` whenever a
reviewer selects **Edit Commands** or **Reject** on the dashboard. The
five entries below are seed/example entries showing the expected format
and covering a spread of fault types, so the log is populated even
before the first live class review session.

**Current agreement rate (seed data): 83.3%** (25 of 30 cases Accepted
as-is) — the remaining 5 cases needed an edit or were rejected outright,
as detailed below. This number updates automatically as new decisions
are logged via the dashboard (`docs/decision_log.csv`).

### NET-005 — Edited (2026-08-10 14:02 UTC)
- **AI root cause:** "OSPF adjacency likely failing due to a Layer 3
  addressing issue between R1 and R2."
- **Reviewer notes:** AI correctly identified OSPF was down but
  attributed it to addressing rather than area-ID/timer mismatch. Reviewer
  corrected the root cause to "mismatched OSPF area ID between R1 and R2"
  after checking `show ip ospf interface brief`, and edited the proposed
  fix commands accordingly before approving deployment.

### NET-009 — Edited (2026-08-10 14:15 UTC)
- **AI root cause:** "Trunk link between Sw1 and Sw2 is down."
- **Reviewer notes:** The trunk was actually up, but VLAN 30 had been
  pruned from Sw1's allowed-VLAN list. AI conflated "no connectivity for
  VLAN 30" with "trunk down." Reviewer corrected the diagnosis and edited
  the fix to `switchport trunk allowed vlan add 30` instead of a
  trunk-recovery procedure.

### NET-017 — Rejected (2026-08-11 09:40 UTC)
- **AI root cause:** "NAT is completely unconfigured on R1."
- **Reviewer notes:** Rejected — NAT was configured, just as a static
  1:1 translation instead of PAT/overload, so only one host could reach
  the internet. The AI's proposed fix (re-create NAT from scratch) would
  have been unnecessarily disruptive. Reviewer rejected and re-ran
  diagnosis with additional evidence (`show run | include ip nat`),
  which the checker caught correctly (rule `NAT_NO_OVERLOAD`) on the
  second pass.

### NET-019 — Edited (2026-08-11 10:05 UTC)
- **AI root cause:** "Single default route misconfiguration."
- **Reviewer notes:** AI missed that TWO default routes existed with
  different next-hops (dual WAN), which is what caused the asymmetric
  routing symptom. Reviewer edited the root cause and next_command to
  request policy-based routing evidence, and flagged this case for the
  training-example set since the evidence already contained both routes.

### NET-027 — Rejected (2026-08-11 11:20 UTC)
- **AI root cause:** "OSPF cost misconfiguration causing suboptimal
  path selection."
- **Reviewer notes:** Rejected — the actual issue was a routing loop
  from misconfigured redistribution, confirmed by `traceroute` showing
  repeated TTL-exceeded between R1 and R2. A cost misconfiguration would
  not explain a loop. Reviewer rejected the AI diagnosis entirely rather
  than editing it, since the root cause category itself was wrong, and
  logged this as a case to add to future few-shot examples in
  `diagnose_prompt.md`.

## How to interpret this log

- **Accepted** — AI diagnosis matched the reviewer's independent
  assessment; deployed as proposed.
- **Edited** — AI direction was broadly correct but needed a reviewer
  correction to the root cause, evidence citation, or fix commands
  before approval.
- **Rejected** — AI diagnosis was substantively wrong; reviewer
  performed independent diagnosis and did not deploy any AI-proposed
  commands.

This log, together with `docs/decision_log.csv` (machine-readable,
generated by the dashboard), is the primary artifact for the
Responsible AI deliverable required by the project brief.
